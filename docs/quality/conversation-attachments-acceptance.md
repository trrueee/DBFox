用户授权构建新的安装包、检查当前安装版SQLite兼容性、使用提供的DeepSeek凭据进行真实模型自动化测试并保留截图。凭据仅进入OS凭据库；真实模型只接收合成验收文件和问题，不接收用户现有会话内容或数据库备份。

## 验收基线与顺序

1. 读取当前安装文件的版本、最终Sidecar manifest/hash和数据库迁移版本。使用SQLite backup API建立一致性私有副本；在副本上迁移并比较旧表内容摘要、FK、FTS及重新启动结果，不直接改写日常数据库。
2. 为候选生成独立产品版本与不可变DLC版本；沿用原有签名、源码/锁/SQLite provenance、CSP、鉴权与资源边界。正式Windows发布需要Authenticode；本机缺少该证书时只能交付明确标注的本地验收候选，不能宣称已正式签名发布。
3. 先运行生产固定Python与Frozen Sidecar检查，再构建NSIS安装包、运行安装态/打包态smoke，记录最终二进制hash与实际运行版本。
4. 在隔离验收项目中使用真实DeepSeek原生function calling完成首次分析、无新附件追问、重复文件名与历史指代；验证工具记录、SQL Artifact、结果来源和独立金额oracle，避免只按自然语言答案判断。
5. 通过真实桌面窗口检查原生选文件、输入框/历史消息文件入口、右侧只读Dock、工作表、源格式、复制/查找、反复关闭重开、切会话、重启恢复。截图只包含合成数据，保留失败与修复前后证据。
6. 回归异常与边界，再打包最终候选；检查安装包中的代码/工具/SQLite与验收对象一致。仅列出实际执行过的项目，未通过或未覆盖的项目明确保留。

## 实际执行与结论

Windows x64 **1.0.4 本地验收候选**已完成实现、安装态和真实模型业务闭环验证。交付 NSIS 安装包、离线证据包、合成工作簿、独立 oracle、逐项核验脚本、截图及相对开发起点的 Git Diff。安装包和 Sidecar 的 Authenticode 状态为 **NotSigned**；系统 DLC 保留原发布者 Ed25519 签名与精确 digest 检查。此候选未发布到更新服务器，不能称为正式签名发布。

### 当前安装版 SQLite 兼容

实际安装版为 `D:\DBFox` 的 1.0.3（Tauri Host）。实际旧、新 Sidecar 均为 Python **3.14.6 / SQLite 3.53.1**，具有 FTS5；最低合同为 3.51.3。manifest 的 3.53.4 是升级目标，不能当作实际运行版本。未替换系统 SQLite DLL。

使用 SQLite backup API 对日常库建立一致性私有副本，在固定生产解释器上将副本从 `f6a7b8c9d0ec` 迁移到 `f7a8b9c0d0ed`。22 张原业务表的行数及内容摘要不变；完整性检查为 ok、外键错误 0，FTS 查询通过。另复制实际 DLC registry、原包及 5 个 owner 的 SQLite 一致性副本，激活新系统包后验证其 **24 张原表**内容不变、完整性 ok、外键错误 0。原发布者指纹保持不变，没有放宽版本/签名策略。

日常原库、原 DLC registry、旧程序保持原样，末尾另做保全核验。验收不对个人会话启动 Agent，也不把个人数据库发送给模型。真实安装使用独立目录与 runtime，未替用户迁移日常运行目录。正式使用前应关闭旧版及新旧后台进程，备份整个 DBFox runtime 后安装；不要让两个 Host 同时打开同一运行目录。回退应恢复升级前的一致性备份，不能声称旧版能直接读取升级后的 schema。

### 原生交互与只读 Dock

通过真实 Windows 文件选择器添加合成文件；输入框及历史消息入口均实际打开右侧 Dock。安装态核验原始合并标题、样式、数字格式、前导零、冻结行、工作表切换、查找、全屏、十次关闭重开和卸载清理。Delete/输入文字没有改变当前单元格和原件；不重算公式。截图 21–23 为最终样式、查找和切表证据，27–29 为澄清及重启追问证据；早期失败截图单独标识，不能当作通过图。

### 验收中发现并修复

1. SQLite 时间失去时区导致上传 HTTP 成功而 UI 报错：在权威 HTTP 边界统一 UTC 时间，补上传/列表合同回归。
2. Frozen 可执行文件不接受 Python 的 `-m` worker 命令：增加显式 worker 入口，复用原协议，Frozen smoke 实际检查握手。
3. 模型缺少精确引用语法及校验 Artifact ID：补公开的引用格式、具体完成条件反馈和工具返回字段；未放宽 SQL 或引用验证。
4. 重叠结果读取再次 SET 已锁配置引发间歇 503：锁配置移至 DuckDB 创建参数；重叠连接回归与 16 并发实际 HTTP 读取通过。
5. 网格全屏后未重绘、主题替换丢 alpha 遮挡选区：利用既有重绘机制并保留透明度；安装态复核通过。
6. 多工作表最初自行合并而未澄清（TC-08 失败）：将 Data Guidance 绑定到首轮附件资源，明确先澄清再 prepare；保留失败记录，修复后实际 UI 澄清与 210.00 结果通过。
7. 一次家居解释错误声称存在未支付排除行，金额本身正确。追查真实明细后纠正，Guidance 要求解释前取得诊断证据；最终重启追问的排除对账正确。模型文字仍可能出错，不能把本次通过描述为任意报表理解都必然正确。
8. 系统包资产清单遗漏 Story、vendor 构建写后立即读取在 Windows 偶发失败：复用唯一清单、在内存完成变换后一次写入。DLC 同版本不同 digest 被正确拒绝，采用新版本，未加绕过或 fallback。

安装收口时 C 盘空间耗尽，导致一次 NSIS 返回 2、Sidecar 文件与 manifest 不一致，以及 smoke 的 SQLite `database or disk is full`。这不是 schema 迁移不兼容。保留失败记录后，将仅属于本次验收的 51 份临时解包目录和私有备份转存 D 盘，C 盘恢复约 4.9 GB；重新安装返回 **0**，Sidecar、app.asar、5 个系统包与构建产物逐一一致，启动及真实模型补测通过。连续工具调用复用单一解包目录，不是每次分析泄漏一份。既有 Windows Host/smoke 强制结束进程树仍可能遗留 PyInstaller 临时解包目录，本次没有改造进程关闭协议；密集重启和长期运行需继续跟踪这一清理问题。验收后暂存文件保留在私有目录，未纳入公开交付。

最终 Data 系统包版本为 **2.2.7**（包括最后一次无行为变化的重复 import 清理），Music 0.3.1；其余以交付 manifest 为准。每次候选升级保留不可变版本策略。
