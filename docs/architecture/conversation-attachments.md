## 目标与范围

用户每条消息添加一份 xlsx 并提问，同一会话可多次添加文件，后续根据稳定 ID、发送顺序和已执行分析的证据引用历史文件。同名文件不覆盖。不建立数据导入管理系统，不用界面当前选中文件推断 Agent 权限。结果必须来自真实读取和既有 SQL 校验、不可变 Artifact、只读执行链。

2026-10-27 用户审核独立预览原型后，授权收口技术问题并进入第四阶段增量开发。第五阶段已完成 Windows x64 安装候选、真实模型及旧版数据副本升级检查，见[验收与交付记录](../quality/conversation-attachments-acceptance.md)。正式发布的 Windows 代码签名仍待配置。

## 所有权与公开边界

Host 在 Agent Kernel 外保存不可变原始字节、附件 ID、哈希、会话归属及首次输入关联；Kernel 只接纳通用引用。Data DLC 通过公开 SDK 获取授权的只读句柄，拥有工作簿读取、预览表示和可再生 DuckDB 数据集。DLC 不读取 Host ORM，不导入 Engine 或 Renderer 私有实现。

资源目录组合已有项目资源与可选会话资源；会话目录以当前 Run 已处理输入的顺序为上界，后续排队输入不提前可见。每个 Invocation 仍冻结精确 ResourceRef，并在执行及结果读取边界检查来源有效性。附件字节或派生资源不可跨会话被猜 ID 访问。

### Kernel 与 Stable SDK 演进依据

1. 这是现有 Project-only authority 无法表达会话私有输入的授权与持久化正确性问题；不以实现方便或虚构两个现有领域需求作为理由。
2. 既有 Operation、Context、Guidance 和对象引用都不能证明会话成员关系；同 Run Artifact 也不能承载长期历史附件身份。
3. Data owner 无权接纳 Host 输入或读取 Host 会话表，必须由 Host 提供可信范围。
4. 新增可选会话资源贡献、只读附件句柄及 session Operation，保持能力中立、owner-bound、缺少可信上下文时拒绝。
5. 不新增旧新双写、映射表或 fallback。会话和项目是两个真实作用域。原件到第三方网格只在 Data 前端边界转换一次。
6. API v2 采用兼容新增，既有 Project provider 语义不变；旧 Run 不因缺少引用而获得附件。更新公开表面快照、文档及 conformance 测试。
7. 验证包括同项目跨会话、未来输入、版本变化、删除/取消、恢复、旧 DLC、SQL Artifact 链及前端卸载。

## 读取、计算与预览

复用 openpyxl / defusedxml 读取 xlsx。选定单层唯一表头的明细，保留来源行列；金额使用受检 Decimal / DuckDB DECIMAL。混合类型、必要值缺失、业务口径和多个合理工作表必须明确处理；不能静默把非法金额转成零。计算涉及公式列时要求值副本，预览可展示原有缓存但不重算。禁止宏和外部链接访问。

### 分段工作表

Data 2.3.0 的 `workbook_inspect` 接受 `cell_range`，每次最多64行、16列，默认读取左上角32行、8列。返回带原始行号的有界样本、表头候选的单元格坐标、已检查的最后行及 `next_range`；响应达到字节预算时按行停止，下一范围从未返回的行继续。样本文本截取会标明列，检视不代表全表计算。读取后续页仍保留前面出现的敏感字段遮蔽规则。

`workbook_prepare` 先解析用户选择的列，再验证这些表头是否唯一、有效。未选中的空白、格式扩展列不影响准备；重复的所选表头仍拒绝。不指定列时要求单层完整表头，尾部空白列含业务数据时明确拒绝，不能自动丢弃。

对于标题、重复表头、明细、合计和附表混排的工作表，使用最多24个显式 `regions`，每个 `data_range` 只包含明细，所有区块使用同一个 `header_row` 和所选列的物理位置。区块不能重叠，不能越过实际数据边界；标题、合计、重复表头和附表应在区块外。不同列布局应分别准备，不推测列名映射。区块内非法或缺失的业务值仍拒绝，不允许用缩小范围掩盖数据问题；业务排除仍须用户授权并保存原始行号与原因。

区块可用 `context_cells` 将分类字段引用到本表真实文本单元格，例如 `{"课程类别":"A16"}`。引擎从原件取值，模型不能填写分类常量。所有区块使用相同的上下文字段名，每块最多4个；公式、空值、错误或非文本不能作为分类来源。新增字段为 VARCHAR，`source_column=null`，具体来源在区块配方中；普通字段保留物理列号。每条明细保留 `__source_row`。完整区块、分类来源、排除行、所选列和解析器版本参与不可变配方与来源记录，并记录区块外的非空行数。这个数量包含标题/说明等，只表示覆盖范围，不能当作被排除的业务记录数。

Data 的 Guidance 要求先读相关区块及说明，区分选修备选、毕业要求和多学期标签。不能把选修清单总和当作毕业要求，也不能自行把多学期课程学分拆分或重复计入各学期。尚未解决的业务口径由既有澄清工具确认。准备后的分类、精确数值及覆盖范围仍通过现有 SQL 校验、Artifact 和只读执行链核实。

结构检视与数据准备分别投影有界耐久事实：原件哈希、工作表/单元格范围、表头位置、配方/结构指纹及行列数量。样本不进入耐久事实。不同工作表或范围形成不同的有效进展，重复读取同一范围形成相同证据；不修改 Core 的停滞阈值、错误规则或领域中立性。

实现前比较了项目已有 openpyxl/DuckDB、openpyxl 的只读遍历和地址工具，以及 pandas 的 `read_excel(usecols, skiprows, nrows)`。继续复用现有依赖，在 Data owner 的真实文件边界加入少量范围校验和出处元数据。pandas 的自动 DataFrame 读取不能替代合计/选修的业务口径与原始单元格出处，且引入额外依赖；没有新增兼容层、字段重命名表、SQL 旁路或 Kernel 分支。官方参考：[openpyxl 只读模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)、[地址工具](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.utils.cell.html)、[pandas read_excel](https://pandas.pydata.org/docs/reference/api/pandas.read_excel.html)。

DataConnectionBoundary 增加受管理 DuckDB 来源，沿用 SQL 工具、结果 Representation、取消及版本校验。只读连接关闭外部访问和自动扩展，锁定配置；不能把模型原始 SQL 直接送入新执行旁路。

锁定配置在 DuckDB 连接创建时一次设置，避免重叠只读连接再次执行 SET 引起配置已锁定错误。SQL 校验观察明确返回 SQL Artifact 的 `validation_artifact_id`，执行工具直接消费它；安全 Artifact 不充当执行输入。工作簿不创建网络连接 Profile；网络样本预览工具明确拒绝工作簿句柄，结构检查和经过校验的 SQL 已覆盖需要的读取路径。

Data DLC 的工作簿 Guidance 从附件资源可见时即生效：先检查原件，存在多个合理工作表时在准备和计算前通过既有澄清工具确认；追问保留已确认文件、工作表和口径。解释排除原因必须查询明细或诊断，不从合计数推测。Guidance 是模型行为约束，仍需真实模型用例验证，不能视为任意自然语言都正确的证明。

预览采用 FortuneSheet 1.0.4，复用 Host React，懒加载静态资产，保留现有 CSP。原型的可选 afterCellMouseDown Hook 捕获已失效的 Immer draft；正式视图不注册该诊断 Hook。原有公开选择 API 足以定位来源。针对 Core 的 uuid 依赖使用已测试的 11.1.1 override，不引入 ExcelJS、FortuneExcel 或 Univer。

Dock 尺寸变化通过 ResizeObserver 通知现有网格重绘；卸载时取消观察和待执行帧。主题转换保留原色 alpha，避免半透明选择层变成不透明遮罩。初始选择保持有效 A1 地址，预览不开放编辑或原件写入。

现有 DlcOperationSpec 支持每个操作声明响应预算，Host 硬上限为 10 MiB。预览单独设 8 MiB，每次只加载一个工作表，最多 10,001 个总行、128 列。普通 openpyxl 读取会保留其他工作表，故读取前限制整本工作簿的存储单元格与合并区域展开预算之和不超过 125,000；这是保守的内存预算，不是截取前 125,000 个单元格。任一上限触发都明确拒绝预览。分析采用独立的 100,000 明细行、128 列、1,000,000 存储单元格预算；原始附件每份 10 MiB、会话 10 份/100 MiB、解压后 100 MiB。未发送附件及中断上传临时文件超过 24 小时清理。

Host 原件使用服务器 ID 与 `.blob` 存储；Data 把校验后的有界字节流交给 openpyxl，不依赖存储扩展名判断格式。原件与派生 DuckDB 都校验哈希。派生文件缺失可按相同原件和配方重建，原件缺失不能用缓存冒充有效来源。公式分析要求值副本；日期空值保留 NULL 和数量，数值列缺值或非法值明确拒绝；全量准备同时记录货币域与用户授权的排除行。

产品 Context 与 ArtifactRepository 共用注入的当前 Run 资源目录检查历史 Artifact 精确资源版本，并保留既有生产者证明、会话、可见性和 Run 顺序约束。否则没有重新附加文件的追问会被旧的初始 Input fence 错误屏蔽。此注入不修改已接纳 Input，不跳过 SQL 的当前 Run 校验，不授予其他会话或未来输入的资源。没有该产品目录的 Kernel 调用仍按其显式接纳范围检查。已消费的运行中补充输入可以更新显式引用；队列输入不能更新。

删除通过 Host 持久化清理记录交付 Data owner，分别确认原件和派生文件清理。owner 禁用或暂时失败时保留记录，重启后重放；清理记录不恢复访问权限。

文件级开发计划与开发验证记录在[第四阶段实施记录](../archive/reviews/conversation-attachments-implementation.md)，安装态、旧库迁移、生产固定 Python 和真实模型结果记录在[第五阶段验收](../quality/conversation-attachments-acceptance.md)。Frozen Sidecar 通过显式 `--tool-worker` 入口启动既有隔离 worker，开发态仍使用模块入口。上传时间在 HTTP 边界统一为 UTC 带时区时间，匹配生成的前端合同。上述修复均复用现有边界，没有引入兼容层或另一套 Agent/SQL 执行链。
