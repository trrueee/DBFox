# DBFox 术语表

> 文档类型：参考
>
> 状态：当前
>
> 最后核验：2026-08-12

> 适用范围：DBFox 产品、桌面端、Python Engine、Agent 和发布文档

本文统一项目中反复出现的术语。代码符号仍以源码为准；文档描述应优先使用本表中的名称，避免为同一概念重复造词。

## 产品与运行时

| 术语 | 通俗解释 | 不要混淆 |
| --- | --- | --- |
| Rust Host | Tauri 的 Rust 进程，负责桌面窗口、Sidecar 生命周期、端口、令牌和系统能力 | React 页面或 Python 业务服务 |
| Sidecar | 随桌面应用一起分发并由 Rust Host 启动的 Python Engine 进程 | 第二套后端实现 |
| Runtime Supervisor | Rust Host 中监督 Sidecar 启动、退出和重启的组件 | 前端网络重试逻辑 |
| generation（运行代次） | 每次 Sidecar 成功启动后的代次编号，用于识别过期端口和令牌 | 数据库结构版本 |
| 运行时令牌 | Rust Host 为本次 Sidecar 运行生成的短期本地访问令牌 | Provider API Key 或数据库密码 |
| WebView | Tauri 窗口中承载 React 界面的网页运行环境 | 普通浏览器发布版本 |

## 数据与 SQL

| 术语 | 通俗解释 | 不要混淆 |
| --- | --- | --- |
| 元数据数据库 | DBFox 自己使用的本地 SQLite，保存配置、会话、事件和结果索引 | 用户连接的业务数据库 |
| 数据源 | 用户在 DBFox 中保存的外部数据库配置 | 一个永久打开的连接 |
| Catalog（目录） | 数据源中的 schema、表、字段和关系等结构信息 | 实际业务数据行 |
| 只读 SQL | 经过解析和策略检查、不会修改数据源状态的查询 | 仅靠字符串前缀判断的 SQL |
| 参数绑定 | 把 SQL 结构和值分别交给数据库驱动执行 | 把值拼接进 SQL 字符串 |
| Result Artifact（结果制品） | 可持久引用、分页读取和继续分析的查询结果 | 一次性塞入模型上下文的完整行集 |
| Observation（工具观察） | 工具执行后提供给 Agent 的有界结构化结果 | 原始数据库转储或日志全文 |

## Agent 运行

| 术语 | 通俗解释 | 不要混淆 |
| --- | --- | --- |
| Agent Harness | 组织模型请求、工具调用、状态、持久化、取消和恢复的完整运行系统 | 一个提示词文件 |
| Provider | 提供模型 API 的外部服务及其边界适配 | DBFox 领域状态机 |
| Session（会话） | 可以包含多次用户输入和多次运行的对话容器 | 单次模型请求 |
| Input（输入） | 用户提交到会话的一次耐久请求 | Provider message |
| Run（运行） | Agent 消费一次输入并形成结果的完整执行 | 单次 Turn |
| Turn（轮次） | 一次模型请求、响应和工具决策边界 | 整段会话 |
| RunItem（运行项） | 消息、工具调用、工具结果和状态等统一持久化记录 | UI 临时卡片模型 |
| function calling（函数调用） | Provider 的结构化工具调用协议，使用 `call_id` 配对调用和结果 | 从自然语言中猜测工具参数 |
| Completion（完成判断） | 根据正常终止、文本、工具状态和错误状态决定本轮是否结束 | 仅检查某个 Provider 的可选字段 |
| Context（当前上下文） | 本轮模型实际接收的有界消息和工具信息 | 完整聊天历史 |
| Memory（工作记忆） | 从已完成事实中提炼、可重新生成的有界会话信息 | 全量消息数据库 |
| Recall（历史查找） | 在权限、范围和预算限制下搜索并读取较早消息 | 自动注入全部历史 |
| Evidence（证据） | 支撑回答结论的可追溯结果引用 | 模型自行生成的引用文字 |

## 状态、错误与恢复

| 术语 | 通俗解释 | 不要混淆 |
| --- | --- | --- |
| 耐久事实源 | 进程重启后仍能恢复、由数据库事务维护的权威状态 | 内存缓存或前端 Store |
| 投影 | 从耐久事实计算出的界面或缓存视图，可以重新生成 | 第二份业务事实 |
| lease（租约） | 限时、带围栏信息的执行所有权，防止两个 worker 同时处理同一会话 | 只在单进程内生效的锁 |
| cursor（游标） | SSE 客户端记录的事件位置，用于断线后继续读取 | 数据库分页页码 |
| snapshot（快照） | 客户端丢失或缺少事件时，用于恢复当前公开状态的完整投影 | 数据库备份 |
| Problem Details | RFC 9457 定义的 HTTP 错误响应格式 | 把内部异常文本直接返回给 UI |
| 公开错误 | 经过固定目录或明确许可、可以展示给用户的错误信息 | 任意异常对象的 `message` |
| 故障注入 | 主动终止进程、断开流或制造错误以验证恢复行为 | 单纯阅读代码推断结果 |

## 发布与验证

| 术语 | 通俗解释 | 不要混淆 |
| --- | --- | --- |
| Frozen Sidecar | 由 PyInstaller 等方式冻结后的正式 Sidecar 可执行文件 | 开发环境中的 `python` 进程 |
| bundle（安装产物） | Tauri 生成的 MSI、NSIS、AppImage 或应用包 | 只完成编译的中间文件 |
| smoke（冒烟验证） | 对正式构建运行最小关键链路，证明产物能启动并完成基本合同 | 完整功能回归 |
| 静态发布合同 | 对配置、目标平台和构建脚本的代码审查 | 真实平台构建、安装和运行通过 |
| 发布门禁 | 发布前必须满足并留下证据的检查 | 一般改进建议 |

## 写作约定

- 正文优先写“工具调用”，只有讨论 Provider 协议时才写 `function calling`。
- 正文优先写“当前上下文”“工作记忆”“历史查找”，首次出现时在括号中保留代码术语。
- `RuntimeSupervisor`、`ContextAssembler`、`AgentRun` 等源码符号使用反引号，不翻译成新的类名。
- 没有真实验证证据时写“未验证”，不要写“理论支持”“应该可用”或“视为通过”。
